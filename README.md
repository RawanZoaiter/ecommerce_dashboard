# لوحة إدارة المتجر — E-Commerce Admin Dashboard

لوحة تحكم للمسؤولين، مبنية بـ Flutter Web، لمشروع مادة تطبيقات الإنترنت (الفصل الدراسي 2026).
تعرض المنتجات والطلبات وتديرها، وتتصل بالـ REST API المبني بـ Laravel.

**اللوحة مربوطة بالـ API الحقيقي.** لا توجد بيانات تجريبية في المشروع: كل شاشة موجودة لها
endpoint فعلي خلفها، وما لا endpoint له فليس موجودًا في الواجهة.

## التشغيل

شغّلي الباك إند أولًا (وخدمة المخزون قبله)، ثم:

```bash
flutter pub get
```

```bash
flutter run -d chrome --web-port=5000
```

عنوان الـ API الافتراضي `http://localhost:8080/api`. ولتغييره — مثلًا للعمل على جهاز زميلة
في نفس الشبكة:

```bash
flutter run -d chrome --dart-define=API_BASE_URL=http://192.168.1.5:8080/api
```

الدخول بحساب المسؤول الموجود في دليل الواجهة. الدخول بحساب زبون يُرفض برسالة خاصة: هذه
لوحة إدارة، والسيرفر سيرفض عملياتها بـ 403 على أي حال.

## الشاشات

| الشاشة | الـ endpoints |
|---|---|
| تسجيل الدخول | `POST /auth/login` · `GET /auth/user-info` · `POST /auth/logout` |
| الرئيسية | `GET /orders` (عدّاد لكل حالة) · `GET /products` |
| المنتجات | `GET /products` · `GET /categories` |
| تفاصيل المنتج | `GET /products/{id}` |
| إضافة منتج | `POST /products` (multipart) |
| الطلبات | `GET /orders` |
| تفاصيل الطلب | `GET /orders/{id}` · `PATCH /orders/{id}/status` |

تجديد الـ tokens يجري تلقائيًا عبر `POST /auth/refresh` في طبقة الشبكة، دون أن تعرف أي شاشة
بذلك.

## البنية

```
lib/
├── main.dart · app.dart          نقطة الدخول وإعداد MaterialApp
├── core/
│   ├── config/                   الـ baseUrl والمهل والحدود
│   ├── di/                       تجميع الاعتماديات (get_it)
│   ├── error/                    Failure و Result وتحويل أكواد الـ API
│   ├── network/                  Dio والغلاف الموحّد والـ interceptors
│   ├── storage/                  تخزين الـ tokens
│   ├── router/                   go_router وحارس الدور
│   ├── theme/                    الألوان والخطوط والمسافات
│   ├── utils/                    Money والتواريخ والأرقام والتحقق
│   └── widgets/                  مكوّنات الواجهة المشتركة
├── features/<الوحدة>/
│   ├── domain/                   الكيانات وواجهات الـ repository
│   ├── data/                     models و datasources و تنفيذ الـ repository
│   └── presentation/             الـ cubits والشاشات
└── l10n/                         ملفات ARB (عربي/إنجليزي)
```

الشاشات تعتمد على واجهات الـ repository في `domain/` فقط، ولا تعرف شيئًا عن Dio ولا عن
شكل الـ JSON. و`core/di/injector.dart` هو المكان الوحيد الذي يعرف كيف تُنفَّذ كل واجهة.

## القرارات التقنية

**الأسعار أعداد صحيحة.** الدليل يقول إن `price` نص بمنزلتين عشريتين ولا تُجرى عليه عمليات
عشرية عائمة. `Money` تخزّن القروش كـ `int`، فمجموع سطور الطلب دقيق تمامًا. مغطّى في
`test/money_test.dart`.

**تجديد التوكن مرة واحدة فقط.** الدليل يحذّر أن كل `refresh_token` يُستعمل مرة واحدة، وأن
طلبَي تجديد متزامنين ممنوعان — واللوحة تطلق طلبات متوازية. `RefreshInterceptor` يستعمل
`QueuedInterceptor` مع قفل واحد، ويقارن التوكن المُرسَل بالمخزَّن قبل التجديد حتى لا يصرف
طلب ثانٍ تجديدًا زائدًا.

**`available_quantity` بقيمة `null` غامضة.** تعني إما أن خدمة المخزون متوقفة أو أن المنتج
بلا سجل مخزون، ولا شيء في الـ API يفرّق بينهما. لذلك تُعرض «الكمية غير معروفة» بدل تخمين
أحد الاحتمالين. يُحسم حين يذكر `GET /app-status` حالة المخزون.

**إخفاء الشاشات ليس أمانًا.** حارس الدور يخفي المسارات، لكن كل شاشة تتعامل مع 403 أيضًا،
لأن الدور يُقرأ من قاعدة البيانات مع كل طلب وقد يتغيّر والتطبيق مفتوح.

**ما حُذف ولماذا.** شاشات المخزون والمستخدمين والإشعارات، وعدّادا الإيرادات والمخزون
المنخفض، وحقل البحث: كلها بلا endpoints. رقم تقريبي يبدو موثوقًا وهو خاطئ أسوأ من غيابه.

## نقطة مفتوحة

**نظام الأرقام في الواجهة العربية.** مكتبة `intl` تكتب أرقام الـ `ar` لاتينية (`20`) وتواريخ
الـ `ar` عربية-هندية (`٢ نوفمبر ٢٠٢٦`)، فالشاشة الواحدة تخلط النظامين. التوحيد قرار منتَج:
إما أرقام لاتينية بالكامل مع تغيير تنسيق التاريخ، أو عربية-هندية بالكامل مع تحويل يدوي. كل
التنسيق يمرّ عبر `core/utils/number_formatter.dart` و`core/utils/date_formatter.dart`، فلا
مكان آخر يحتاج تعديلًا.

## المطلوب من فريق الباك

| المطلوب | الأثر على اللوحة |
|---|---|
| `available_quantity` في `GET /products` | لا عمود كمية ولا عدّاد مخزون منخفض. يحتاج عملية batch في الـ proto، لأن `GetStock` تأخذ منتجًا واحدًا |
| مسار لتعديل المخزون | المنتج المُضاف من اللوحة غير قابل للطلب. يحتاج عملية جديدة في الـ proto وفي خدمة الـ .NET |
| `inventory` في `GET /app-status` | للتمييز بين «الخدمة متوقفة» و«بلا سجل مخزون» |
| `GET /users` | شاشة المستخدمين محذوفة حتى يوجد |
| endpoints الإشعارات | شاشة الإشعارات محذوفة حتى توجد |
| `GET /admin/stats` | أرقام الصفحة الرئيسية تأتي من ستة نداءات بدل واحد |
| `?search=` في `GET /products` | لا بحث بالاسم |

الواجهة لا تتصل بخدمة المخزون مباشرة أبدًا؛ كل ما يخص الكميات يمرّ عبر لارافيل.
